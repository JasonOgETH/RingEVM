# RingEVM — Contracts

On-chain contracts for **RingEVM**, a shielded pool for private, compliant payments on EVM. This repository contains the Solidity source — the shielded pool, the Groth16 verifiers, the incremental Merkle tree, and the programmable **Rings** compliance layer — together with the Foundry test suite.

Website: https://ringevm.xyz · Docs: https://ringevm.xyz/docs

> **Public beta.** These contracts are deployed and source-verified on mainnet, but the system is **unaudited** and the trusted setup is **not yet ceremony-grade**. Do not use with funds you can't afford to lose until independent audits and the production trusted-setup ceremony are complete.

## What's in here

| Path | Description |
|------|-------------|
| `src/ShieldedPool.sol` | The shielded pool — deposit (shield), private transfer, withdraw (unshield), with nullifiers + commitments. |
| `src/IncrementalMerkleTree.sol` | Append-only commitment tree. |
| `src/hashers/PoseidonT3Hasher.sol` | Poseidon(T3) hasher. |
| `src/verifiers/*` | Groth16 verifiers — shield, transact 2×2 / 4×2, policy. *Generated by snarkjs; GPL-3.0 (see note below).* |
| `src/Groth16VerifierAdapter.sol` | Adapter exposing the raw verifiers behind `IVerifier`. |
| `src/rings/*` | The compliance layer — `RingRegistry`, `RingFactory`, `PolicyModule`, `CrossRingRouter`. |
| `src/libraries/*`, `src/interfaces/*` | Shared libraries and interfaces. |
| `src/examples/*` | Example integrations (private swap, private escrow). |
| `test/*` | Foundry tests — unit, invariant, and fork tests. |
| `script/Deploy.s.sol` | Deployment script. |

## Build & test

Requires [Foundry](https://book.getfoundry.sh/). Dependencies are not vendored — install them with `forge install`:

```bash
forge install foundry-rs/forge-std
forge install OpenZeppelin/openzeppelin-contracts@v5.1.0
forge install vimwitch/poseidon-solidity

forge build
forge test
```

Built against forge-std 1.17.0, OpenZeppelin Contracts 5.1.0, and poseidon-solidity 0.0.5.

## Security

- The core pool is **non-upgradeable** and has **no admin key** that can freeze or seize funds.
- Static-analysis configuration is in `slither.config.json`.
- Independent audits (circuits + Solidity) and a public, multi-party trusted-setup ceremony are in progress.
- **Responsible disclosure:** please report vulnerabilities privately via this repository's **Security → Advisories** (GitHub private vulnerability reporting) rather than a public issue.
